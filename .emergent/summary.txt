<original_problem_statement>
The user wants to build a mobile app, GeoPunch, for employee time tracking. Initially, it was designed as a B2B tool with automatic geofence-based punches for a single, admin-assigned workplace.

However, the project underwent a major pivot to become a B2C, personal time-tracking tool for employees to maintain their own records for self-control and evidence (e.g., for overtime disputes).

**Current Product Requirements (Post-Pivot):**

1.  **Multi-Workplace Management:**
    *   Users can create and manage multiple personal workplaces.
    *   Only one workplace can be active at a time for tracking.
    *   Workplace location (lat/lng) is set once via a map-picker during creation and is then **locked** and immutable. To change a location, a new workplace must be created.
    *   Workplace properties include: name, locked location (lat/lng), radius, workdays (Mon-Sun booleans), and an optional, non-enforced schedule.
    *   Edits to non-location fields (radius, workdays, schedule) are audited.

2.  **Assistive Geofencing & Manual Punching:**
    *   Geofencing is **assistive**, not automatic. It sends notifications suggesting a punch when entering/leaving the active workplace's geofence.
    *   The user must manually confirm all punches (Clock In, Clock Out, Break Start, Break End).
    *   Punches are allowed even when outside the geofence, but they must be flagged as such and store relevant data (distance from workplace, etc.).

3.  **Data Integrity & Evidence:**
    *   Each punch must store evidence data: device timestamp, server timestamp, lat/lng, GPS accuracy, distance to workplace, and a snapshot of the workplace location.
    *   The backend must enforce data integrity rules (e.g., immutable location, audit logs).

4.  **Data Export:**
    *   Users can export their own timesheets for a given date range to CSV and XLSX.
    *   The export must include all evidence data, such as punch location, workplace location, and flags for punches made outside the geofence.

5.  **Authentication & Security:**
    *   JWT-based custom auth (email/password) with refresh token rotation.
    *   Passwords must be securely hashed (e.g., bcrypt).

6.  **Tech Stack & Language:**
    *   Frontend: React Native with Expo.
    *   Backend: FastAPI with Python.
    *   Database: MongoDB.
    *   UI Language: Portuguese (pt-PT).

</original_problem_statement>
